## [Google Announces Post-Quantum Cryptography Integration in Android 17](https://security.googleblog.com/2026/03/post-quantum-cryptography-in-android.html) ⭐️ 9.0/10

Google has announced the integration of post-quantum cryptography (PQC) standards into Android 17, specifically upgrading the bootloader to include quantum-resistant digital signatures and migrating the Android Keystore system to a PQC-compliant architecture. This represents a foundational security upgrade for billions of Android devices, proactively protecting the mobile ecosystem against future quantum computing attacks that could break current encryption. It sets a critical precedent for the entire industry's transition to quantum-resistant security. The upgrade targets two critical security components: the bootloader signature chain (to prevent tampering during device startup) and the Keystore (to secure authentication and sensitive data transmission). This implementation follows the finalized PQC standards released by NIST in August 2024.

telegram · zaihuapd · Mar 26, 07:09

**Background**: Post-quantum cryptography refers to cryptographic algorithms designed to be secure against attacks by both classical and quantum computers. Current widely-used public-key cryptography (like RSA and ECC) is vulnerable to being broken by sufficiently powerful quantum computers using Shor's algorithm. In response, standardization bodies like NIST have been working to finalize new PQC algorithms. The Android Keystore is a system that securely stores cryptographic keys on the device, protecting them from extraction.

## [LiteLLM PyPI compromise: 47,000 malicious downloads in 46 minutes, 88% of dependent packages lacked version pinning](https://simonwillison.net/2026/Mar/25/litellm-hack/#atom-everything) ⭐️ 8.0/10

Analysis of the BigQuery PyPI dataset revealed that during a 46-minute compromise of the LiteLLM Python package on PyPI, the malicious versions 1.82.7 and 1.82.8 were downloaded 46,996 times. The analysis also found that 88% of the 2,337 packages that depend on LiteLLM did not use proper version pinning that would have prevented installation of the compromised releases. This incident highlights the severe and rapid impact of supply chain attacks in the Python ecosystem, demonstrating how a brief compromise of a popular library can affect tens of thousands of downloads within minutes. The high percentage of dependent packages without proper version pinning exposes a widespread vulnerability in dependency management practices, putting many projects at risk of similar attacks. The analysis was conducted using Google BigQuery's public PyPI dataset, which streams download logs from PyPI for analysis. The compromised packages were live for only 46 minutes, yet they achieved nearly 47,000 downloads, indicating the high usage volume of the LiteLLM library.

rss · Simon Willison · Mar 25, 17:21

**Background**: LiteLLM is an open-source Python library that provides a unified interface to call over 100 different large language model (LLM) APIs (like OpenAI, Anthropic, and Vertex AI) using the OpenAI format. PyPI (Python Package Index) is the official repository for Python software packages, where developers publish and install libraries. Version pinning is a security and reproducibility practice where a project explicitly specifies the exact version (or a narrow, compatible range) of a dependency it requires, preventing automatic installation of new, potentially compromised versions.

## [Apifox Desktop Client Compromised in Supply Chain Attack via CDN Script Tampering](https://t.me/zaihuapd/40514) ⭐️ 8.0/10

The Apifox desktop client was compromised in a supply chain attack where attackers tampered with an event-tracking script hosted on its official CDN, injecting obfuscated malicious JavaScript code. This malicious payload, active since March 4, steals SSH keys, Git credentials, shell history, and process information from affected Windows, macOS, and Linux systems. This attack is significant because Apifox is a widely-used API development tool, and a supply chain compromise of this scale directly targets developers and organizations, potentially leading to massive credential theft, unauthorized access to code repositories, and further lateral movement within networks. It highlights the critical risks associated with relying on external CDNs for serving executable code in developer tools. The attack was independently analyzed and confirmed by security researcher phith0n, who publicly shared the malicious payload analysis. The compromised script was a front-end event tracking file, and the attack vector demonstrates how tampering with a single CDN-hosted resource can compromise a widely distributed desktop application across all major operating systems.

telegram · zaihuapd · Mar 26, 04:19

**Background**: A supply chain attack targets a less-secure element in the software development or distribution process to compromise the final product. CDNs (Content Delivery Networks) are used to host and quickly deliver static files like scripts globally, but if compromised, they can serve malicious code to all users. SSH keys and Git credentials are critical for authenticating access to servers and version control systems like GitHub; stealing them grants attackers access to sensitive infrastructure and source code.

## [Chinese Academy of Sciences Releases 'Xiangshan' Open-Source RISC-V Processor and 'Ruyi' Native OS, Launches Next-Gen Joint Development](https://h.xinhuaxmt.com/vh512/share/13024070?docid=13024070) ⭐️ 8.0/10

On March 26, at the RISC-V Ecosystem Technology Forum of the Zhongguancun Forum Annual Conference, the Chinese Academy of Sciences (CAS) publicly released the 'Xiangshan' open-source high-performance RISC-V processor and the 'Ruyi' native operating system. CAS also initiated a joint development project for the next-generation 'Kunming Lake' architecture and the 'Ruyi' OS, with participation from dozens of major companies including China Mobile, China Telecom, ZTE, Alibaba, Tencent, and ByteDance. This announcement represents a significant step in building a domestic, open-source hardware and software ecosystem in China, reducing reliance on proprietary architectures. The 'Xiangshan' processor's performance reaching international advanced levels and its commercial adoption by multiple chip companies signals a maturing RISC-V ecosystem with potential to challenge established players like ARM and x86 in specific markets. The 'Xiangshan' processor is notable for being the first to offer a globally open-source Network-on-Chip (NoC) interconnect IP, a critical component for multi-core processor design. Commercial chips based on 'Xiangshan' have already been launched by companies like InDie Temporal, Blue Core Computing, InnoSilicon, and ESWIN, indicating it has moved beyond research into industrial-scale deployment.

telegram · zaihuapd · Mar 26, 10:08

**Background**: RISC-V is an open-standard instruction set architecture (ISA) for processors, which allows anyone to design, manufacture, and sell RISC-V chips without paying royalties. This contrasts with proprietary ISAs like ARM and x86. A Network-on-Chip (NoC) is a communication subsystem on an integrated circuit, typically between intellectual property (IP) cores in a system-on-a-chip (SoC). A 'native' operating system is one built from the ground up for a specific hardware architecture, rather than being ported or adapted from an existing system, which can lead to better performance and integration.

It highlights a growing industry trend where user interactions with AI assistants are leveraged to improve models, while enterprise customers retain stricter data controls. The policy explicitly exempts Copilot Business and Copilot Enterprise users, as well as code from private enterprise repositories. Data that may be used for training includes code context near the cursor, comments, documentation, file names, repository structure, navigation patterns, and feedback on suggestions, and this data may be shared with affiliated companies like Microsoft but not with third-party AI model providers.
