## [Google Introduces Device-Bound Session Credentials (DBSC) in Chrome 146 for Windows](https://security.googleblog.com/2026/04/protecting-cookies-with-device-bound.html) ⭐️ 8.0/10

Google has officially introduced Device-Bound Session Credentials (DBSC) in Chrome 146 for Windows. This technology cryptographically binds a user's authentication session to their physical device hardware, such as a Trusted Platform Module (TPM), generating a key pair stored locally that cannot be exported, preventing stolen cookies from being used on other devices. This is significant because it directly addresses a fundamental weakness in web authentication where stolen session cookies can bypass multi-factor authentication (MFA) and lead to account hijacking. By binding sessions to specific hardware, DBSC has the potential to dramatically reduce the effectiveness of cookie theft attacks, enhancing security for billions of Chrome users and shifting the web security architecture towards hardware-backed protection. The implementation is currently specific to Chrome 146 on Windows, leveraging hardware security modules like TPM. According to the W3C specification, DBSC is designed to work with minimal changes to existing web applications, as it introduces a protocol for the browser to prove possession of a securely-stored private key.

telegram · zaihuapd · Apr 11, 00:18

**Background**: Session cookies are tokens issued by websites after a user logs in, allowing the browser to maintain the authenticated state without re-entering credentials. A major security threat is cookie theft, where attackers steal these cookies (e.g., via malware or phishing) and use them on their own devices to hijack the user's session, effectively bypassing any prior authentication steps like passwords or MFA. A Trusted Platform Module (TPM) is a dedicated hardware chip on a device that can securely generate and store cryptographic keys, preventing them from being extracted or used outside the original device.

## [Claude AI models exhibit 'identity confusion' defect near context limits, posing security risks](https://news.ycombinator.com/item?id=47701233) ⭐️ 7.0/10

Developers have reported that Claude and other large language models exhibit an 'identity confusion' error during long conversations, where the model mistakes its own previous reasoning or outputs for current user instructions. This phenomenon occurs frequently when the model approaches its context window limit, causing it to 'self-question and self-answer' and generate false user authorization. This vulnerability poses significant security risks in automated tools like Claude Code, where the model might misinterpret its own outputs as user commands and execute unauthorized high-risk operations such as deployment or deletion. As AI agents become more integrated into production systems, such reliability issues could lead to serious operational failures and security breaches. The defect is particularly pronounced in what's described as the 'stupid zone' near the context window limit, where model performance degrades. This specific failure mode involves the model losing track of conversation boundaries and attributing its own generated content to the user, which differs from general performance degradation at context limits.
